Recommended shape

One workflow. Three bounded model roles.

Interpreter: navigate and propose grounded facts.
Visual verifier: independently read original page images.
Commentator: explain validated checks.

Pydantic AI in the Python fund service. OpenAI initially; provider configuration stays outside domain logic. No autonomous delegation or agent-created workflow steps.

Agreed: searchable PDFs initially

VLM reads are part of the main PDF path, not just an OCR fallback. Text extraction provides indexing and a comparison path. Scanned PDFs can reuse visual reads later, but require another verification policy when text is unavailable.

Continuity with the plans. This extends the late-binding, document-index → ranged-read design and indexing/extraction phases. Raw tables remain semi-structured; only accepted facts enter the canonical financial schema. The current implementation supports fixed-layout CSVs and deterministic commentary. 02 / Attention is an explicit interface
Index first. Read precisely.
A compact index is the initial context, not an entire pack pasted into a prompt. Section IDs and locators let the agent request useful regions while the harness controls volume and scope.




The index contains structure
  • PDF: page count, native bookmarks/TOC, page dimensions/rotation, headings and text/table block bounds.
  • CSV: encoding/dialect, logical-record offsets, nonempty blocks, repeated header candidates and preview records.
  • Every entry: document hash, stable section ID, locator, heading snippet and indexer version.
Missing or unreliable TOCs trigger deterministic heading/block indexing. Unclassified regions stay discoverable. A section label is a navigation hint, never proof of the right fund or period.
Context survives cropping. A ranged read includes the selected region plus its column headings, reporting scope and linked unit/sign footnotes. Permit one bounded expansion when context is incomplete; do not guess a missing unit.

03 / Agreement is a gate, not a confidence score
Two readings. One exact comparison.
The five core figures are opening NAV, calls, distributions, signed income and reported closing NAV. Each needs supported fund/period/currency/scale context before it can enter the calculation.


Path A · original structured/text evidence
Python rereads the proposed CSV cells or PDF text spans. It validates the selected label, current-period column, scope and unit evidence, then normalises exact decimal strings.
LLM interpretation may propose a mapping. A citation that exists is necessary but insufficient: a prior-quarter or investor value must still be rejected.
Path B · independent visual reading
A fresh VLM context reads original PDF regions with their headings and footnotes. It receives the required field names and reporting scope, but no candidate values, prior model answers or expected results.
The interpreter may also use VLM reads for layout. Verification remains a separate, blinded call. Shared models and documents can still produce correlated errors; agreement is not proof of truth.


Two different tolerances. Normalised extraction paths must agree exactly: 0.000000 permitted deviation on core figures. The financial roll-forward keeps its independent USD 0.010000 tolerance. Never average conflicting readings or infer a missing figure by forcing the equation to balance.

What happens when readings disagree?
Request at most one targeted re-read/expanded crop within the existing budget. Preserve both candidates and their provenance. If the discrepancy remains, finish with insufficient_evidence / “Needs input” and no published calculated NAV or difference, consistent with the current conservative behavior. A confident model response cannot override the gate.
CSV and PDF totals can conflict even when text and image readings of the PDF agree. That is CONFLICTING_SOURCES; there is no automatic source-precedence rule. A text/image disagreement is proposed as EXTRACTION_DISAGREEMENT.
For CSVs, rereading raw records is authoritative for characters. A rendered view of the same CSV is only a secondary parsing check, not an independent source of truth. This fixture's PDF supplies a separate layout for testing the two reading paths. Both files are generated from the same synthetic constants; their agreement does not establish independent source truth. A CSV-only pack would need an explicitly defined verification policy; it must not claim PDF/VLM verification.
Searchable PDFs let us compare a text path with a visual path now. Image-only scans can use the same VLM tools later, but losing the searchable-text path is not a moot verification detail: independent OCR, stronger evaluation and possible human review will need a separate acceptance policy.


Commentary explains the result without inventing a cause
After deterministic checks, a tool-free commentator receives accepted facts, check IDs and the outcome. It returns observed findings, optional explicitly qualified hypotheses and next actions with citations. For the first increment, omit causal hypotheses unless a cited source actually supports them.
Validate fact/check membership, amounts and direction; interpolate approved numeric values in code. Arbitrary prose entailment cannot be guaranteed by a schema, so constrain claim types and evaluate groundedness. On invalid output, refusal, timeout or exhausted commentary budget, use the existing deterministic template.
Baseline example: “Calculated NAV is USD 75,000 above reported NAV. The supplied pack does not explain the variance. Request an explanation or corrected figures from the administrator.” The mismatch itself remains valid if commentary generation fails.






04 / Generic runtime, explicit domain boundaries
Pydantic AI, with a small harness
Use provider-neutral typed tools, dependencies and outputs. Configure an OpenAI model supporting images, tool calls and structured output. Capability checks and the same evaluation suite are required before changing providers.


Why this library
Pydantic AI fits the existing FastAPI/Python service, offers multiple providers and accepts typed outputs. UsageLimits provides model-request and successful-tool-call limits.
Keep provider-specific image packaging behind an adapter. Our orchestration, money rules and provenance remain ordinary Python. A graph engine or multi-agent supervisor is unnecessary for this fixed workflow.
Alternatives: LangGraph if durable branching/human pauses become central; a raw provider SDK if there are only tool-free calls. Neither is required for the proposed first slice.
Separate controls

Invocation sketch and failure behavior
# Design sketch: shared_budget and validation functions are application code.
# Invoked in the existing worker thread, not the FastAPI request handler.
index = build_or_load_index(frozen_manifest)
context = ReadOnlyPackContext(index, shared_budget)
proposal = shared_budget.run_agent(
    interpreter, deps=context, prompt=compact_index(index),
    limits=UsageLimits(request_limit=6, tool_calls_limit=24),
)
text_candidates = reread_and_normalise(proposal.output, context)
visual_candidates = shared_budget.run_agent(
    verifier, images=original_regions(proposal.output),
    prompt=scope_and_field_names_only(),  # no proposed figures
    limits=UsageLimits(request_limit=4),
)
facts = gate_exact_agreement(text_candidates, visual_candidates)
decision = deterministic_reconcile(facts)
commentary = draft_or_template(decision, shared_budget)
repository.publish_atomically(decision, commentary)
Missing/ambiguous evidence or a completed read that still disagrees → completed / insufficient_evidence. Provider unavailability, technical parsing failure, or exhausted extraction budget before required verification completes → failed with a specific technical reason. Optional commentary failure → deterministic fallback. Never silently downgrade the verification policy.
Retain existing single-worker and interrupted-run behavior for this increment. On restart an unfinished run fails; it is not automatically resumed or re-billed. A durable workflow engine is a later decision.


Storage, contracts and user-visible provenance
Propose four versioned internal records: document_index (hash + indexer version + JSONB sections); extraction_candidate (field, source, raw reading, proposed mapping, acceptance state); verification_result (compared candidate IDs and exact discrepancies); agent_invocation (role, model/provider, prompt/tool versions, input/output artifact hashes, attempts, timing and usage).
Freeze policy/model/prompt versions in the run snapshot. Retain inspectable model outputs and tool evidence; do not depend on hidden chain-of-thought. Accepted facts, checks and final commentary publish atomically through the existing tables. Diagnostic candidates may exist for failed runs without being published as verified financial facts.
The four public endpoints remain. Extend shared Zod/JSON Schema and the UI deliberately for processing origin, verification status and invocation summaries; today these metadata fields do not exist. Map internal stages to existing public stages initially. Keep the “Fund service” badge and add a separate “AI-assisted extraction” / “Visual verification passed” label.
CSV locator change: messy files have preambles and multiple headers. Add a versioned csv_record locator using one-based logical records across the entire file, column index, block ID and header reference. Preserve the current fixed-layout csv.record_number semantics (data records after its header). The fixture oracle explicitly uses whole-file record indices; it must not be fed unchanged into the legacy locator.
Evidence UI should show original raw values, source unit/sign interpretation, exact location and the independent verification reading. Disagreements need a side-by-side view and an actionable “Needs input” reason. Do not label model confidence as verified accuracy.

06 / Evaluation before publication
Test the workflow and the model separately
Use deterministic tests for the application contract, and opt-in live evaluations for model quality. A scripted model proves orchestration behavior; it does not establish extraction accuracy.


Every CI run
pytest + scripted models
Real readers/renderers and Postgres; Pydantic AI FunctionModel for exact tool interactions and TestModel for schema smoke tests. Disable real model requests globally.
Assert source boundaries, locators, signs/scales, counter exhaustion, exact agreement, atomic publication and template fallback.
Full user journey
Playwright + isolated fixture seed
Seed the new fund only in an isolated test database with an explicit Express grant. Run the real FastAPI workflow with a scripted provider; poll, inspect commentary and download original files.
Assert mismatch, match and Needs input; earlier decisions stay immutable. No rewriting the existing six production-demo fixtures.
Opt-in paid evaluation
Pydantic Evals + OpenAI
Run the same packs against pinned model/prompt configurations. Repeat each scenario, retain traces and compare exact figures, scope, locators, abstention, latency and usage.
No credential required for ordinary CI. Local evaluation reports are sufficient; hosted observability is optional.


Acceptance criteria for this fixture suite
  • Every accepted core amount equals the oracle exactly after normalisation.
  • Every citation resolves to the correct source region, scope, period and unit evidence.
  • Baseline difference is 75000.000000; matched difference is 0.000000.
  • Conflict and injected visual-error cases never publish a numerical conclusion.
  • Source files cannot instruct the agent to bypass checks or read another fund.
  • Every tool/model attempt obeys the declared shared limits, including repair paths.
  • Commentary contains no invented explanation of the variance.
Proposed gate: all assertions pass across three live repetitions per scenario before assist is enabled for this small suite. This is a release gate for these examples, not a statistical claim about real-world accuracy. Grow a held-out set of layouts before broader use.

Readers & index

Shadow interpreter & verifier

Assist behind the exact-agreement gate
Add isolated new-fund seeding, integration/E2E assertions and evidence UI. Require mandatory verification for this policy.
Grounded commentary
Constrained claims with citations, deterministic numeric rendering and template fallback. Then evaluate image-only scans as a separate policy extension.
