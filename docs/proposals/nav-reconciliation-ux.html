Product & UX proposal

The full user workflow

The primary journey is funds → exception → explanation → evidence → next action. These are the additional user needs I would resolve before building the first release.

01 · Required · Shown

Period, entity & currency

Make the reporting date, fund versus investor scope, share class where relevant, base currency and units explicit. Never imply that balances across currencies can be added together.

02 · Required · Outlined

Getting the right pack in

Upload against a fund and period; show required and received documents. Detect duplicate packs, wrong periods and revised versions. A new pack must visibly mark the previous result as out of date.

03 · Required · Shown

More than pass or fail

Distinguish matched, NAV mismatch, awaiting documents, running and processing failure. Show calculation coverage and tolerance. A missing input or technical failure must never look like a NAV mismatch.

04 · Required · Partly shown

Ownership & resolution

Give each exception an owner, next action and review state. Users need notes, reassignment and an explicit approval workflow. An accepted exception must retain the underlying mismatch and the reviewer's reason.

05 · Required · Shown

Trustworthy evidence

Link each decision to a file version, sheet/cell or page, extracted value and normalisation step. The real product needs original-document viewing and correction with an audit trail. Excerpts here are fictional previews.

06 · Required · Partly shown

Safe reruns & history

Show the pack and rules used before starting, then progress and a durable result. Prevent duplicate runs; retain previous outcomes. Production also needs a previous-run drilldown and a comparison of changed inputs and decisions.

07 · Next · Summary export shown

Handover & notifications

Provide a shareable fund/run link, an evidence export and completion notifications. Let reviewers work through a queue without repeatedly returning to the portfolio.

08 · Required · To define

Permissions & sign-off

Define who may upload, rerun, correct inputs and approve a period. Show reviewed versus unreviewed clearly. Agreed tolerance and rule changes should have an owner and effective version.

Prototype boundary: Fund search, filters, detail tabs, source previews, simulated reruns and CSV export work locally. Upload, assignments, approvals and original-file viewing are proposed workflows, not implemented services. Refreshing resets the demo. Q1 deliberately demonstrates an empty period.

Add a fund pack

Proposed intake flow — this concept does not upload files.

  1. Select the fund, entity scope and reporting period.
  2. Drop a ZIP pack or individual supporting files.
  3. Review detected documents, dates, currencies and missing items.
  4. Confirm whether this is a new pack or a revision of an existing pack.
  5. Start reconciliation and return to the fund's progress view.
Required for this demo's check: opening capital, period movements and reported closing NAV. Show which documents supply each input before starting.
